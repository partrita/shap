4  인과적 통찰을 위한 예측 모델 해석 시 주의사항

머신러닝 모델의 예측 성능이 비즈니스나 과학적 의사결정에 사용될 때, 우리는 종종 모델이 학습한 상관관계가 인과관계를 나타낸다고 가정하는 함정에 빠지기 쉽습니다. 이 튜토리얼에서는 예측 모델을 해석하여 인과적인 인사이트를 얻으려 할 때 발생할 수 있는 잠재적인 문제점들을 살펴보고, SHAP을 활용해 보다 신중하고 정확하게 해석하는 방법을 가이드합니다.

# This cell defines the functions we use to generate the data in our scenario

import numpy as np
import pandas as pd
import scipy.stats
import sklearn
import xgboost


class FixableDataFrame(pd.DataFrame):
    """Helper class for manipulating generative models."""

    def __init__(self, *args, fixed={}, **kwargs):
        self.__dict__["__fixed_var_dictionary"] = fixed
        super().__init__(*args, **kwargs)

    def __setitem__(self, key, value):
        out = super().__setitem__(key, value)
        if isinstance(key, str) and key in self.__dict__["__fixed_var_dictionary"]:
            out = super().__setitem__(key, self.__dict__["__fixed_var_dictionary"][key])
        return out


# generate the data
def generator(n, fixed={}, seed=0):
    """The generative model for our subscriber retention example."""
    if seed is not None:
        np.random.seed(seed)
    X = FixableDataFrame(fixed=fixed)

    # the number of sales calls made to this customer
    X["Sales calls"] = np.random.uniform(0, 4, size=(n,)).round()

    # the number of sales calls made to this customer
    X["Interactions"] = X["Sales calls"] + np.random.poisson(0.2, size=(n,))

    # the health of the regional economy this customer is a part of
    X["Economy"] = np.random.uniform(0, 1, size=(n,))

    # the time since the last product upgrade when this customer came up for renewal
    X["Last upgrade"] = np.random.uniform(0, 20, size=(n,))

    # how much the user perceives that they need the product
    X["Product need"] = X["Sales calls"] * 0.1 + np.random.normal(0, 1, size=(n,))

    # the fractional discount offered to this customer upon renewal
    X["Discount"] = ((1 - scipy.special.expit(X["Product need"])) * 0.5 + 0.5 * np.random.uniform(0, 1, size=(n,))) / 2

    # What percent of the days in the last period was the user actively using the product
    X["Monthly usage"] = scipy.special.expit(X["Product need"] * 0.3 + np.random.normal(0, 1, size=(n,)))

    # how much ad money we spent per user targeted at this user (or a group this user is in)
    X["Ad spend"] = (
        X["Monthly usage"] * np.random.uniform(0.99, 0.9, size=(n,)) + (X["Last upgrade"] < 1) + (X["Last upgrade"] < 2)
    )

    # how many bugs did this user encounter in the since their last renewal
    X["Bugs faced"] = np.array([np.random.poisson(v * 2) for v in X["Monthly usage"]])

    # how many bugs did the user report?
    X["Bugs reported"] = (X["Bugs faced"] * scipy.special.expit(X["Product need"])).round()

    # did the user renew?
    X["Did renew"] = scipy.special.expit(
        7
        * (
            0.18 * X["Product need"]
            + 0.08 * X["Monthly usage"]
            + 0.1 * X["Economy"]
            + 0.05 * X["Discount"]
            + 0.05 * np.random.normal(0, 1, size=(n,))
            + 0.05 * (1 - X["Bugs faced"] / 20)
            + 0.005 * X["Sales calls"]
            + 0.015 * X["Interactions"]
            + 0.1 / (X["Last upgrade"] / 4 + 0.25)
            + X["Ad spend"] * 0.0
            - 0.45
        )
    )

    # in real life we would make a random draw to get either 0 or 1 for if the
    # customer did or did not renew. but here we leave the label as the probability
    # so that we can get less noise in our plots. Uncomment this line to get
    # noiser causal effect lines but the same basic results
    X["Did renew"] = scipy.stats.bernoulli.rvs(X["Did renew"])

    return X


def user_retention_dataset():
    """The observed data for model training."""
    n = 10000
    X_full = generator(n)
    y = X_full["Did renew"]
    X = X_full.drop(["Did renew", "Product need", "Bugs faced"], axis=1)
    return X, y


def fit_xgboost(X, y):
    """Train an XGBoost model with early stopping."""
    X_train, X_test, y_train, y_test = sklearn.model_selection.train_test_split(X, y)
    dtrain = xgboost.DMatrix(X_train, label=y_train)
    dtest = xgboost.DMatrix(X_test, label=y_test)
    model = xgboost.train(
        {"eta": 0.001, "subsample": 0.5, "max_depth": 2, "objective": "reg:logistic"},
        dtrain,
        num_boost_round=200000,
        evals=((dtest, "test"),),
        early_stopping_rounds=20,
        verbose_eval=False,
    )
    return model
X, y = user_retention_dataset()
model = fit_xgboost(X, y)

XGBoost 고객 유지 모델을 확보한 후에는 SHAP와 같은 해석 도구를 사용하여 배운 내용을 탐색할 수 있습니다. 먼저 모델의 각 기능에 대한 전체적인 중요성을 플로팅합니다.

import shap

explainer = shap.Explainer(model)
shap_values = explainer(X)

clust = shap.utils.hclust(X, y, linkage="single")
shap.plots.bar(shap_values, clustering=clust, clustering_cutoff=1)

이 막대 그래프는 제공되는 할인, 광고비 및 보고된 버그 수가 모델의 고객 유지 예측을 주도하는 상위 3가지 요소임을 보여줍니다. 이것은 흥미롭고 언뜻 보기에 합리적으로 보입니다. 막대 그래프에는 나중에 사용할 기능 중복 클러스터링도 포함되어 있습니다.

그러나 더 깊이 파고들어 각 특성의 값 변경이 모델 예측에 어떤 영향을 미치는지 살펴보면 몇 가지 직관적이지 않은 패턴을 발견할 수 있습니다. SHAP 산점도는 기능 값 변경이 모델의 갱신 확률 예측에 어떤 영향을 미치는지 보여줍니다. 파란색 점이 증가하는 패턴을 따르는 경우 이는 특성이 클수록 모델의 예측 갱신 확률이 높아짐을 의미합니다.

shap.plots.scatter(shap_values, ylabel="SHAP value\n(higher means more likely to renew)")

4.1 예측 작업과 원인 작업 비교

산점도는 몇 가지 놀라운 결과를 보여줍니다. - 버그를 많이 신고하는 사용자는 갱신할 확률이 높아집니다! - 할인폭이 큰 사용자는 갱신할 가능성이 적습니다!

우리는 버그를 배제하기 위해 코드와 데이터 파이프라인을 세 번 확인한 후 직관적인 설명을 제공하는 일부 비즈니스 파트너와 대화합니다. - 제품을 중요하게 생각하고 사용량이 많은 사용자는 버그를 보고하고 구독을 갱신할 가능성이 높습니다. - 영업사원은 제품에 관심이 없을 것으로 생각되는 고객에게 높은 할인을 제공하는 경향이 있으며 이러한 고객은 이탈률이 더 높습니다.

모델에서 이러한 처음에는 반직관적인 관계가 문제입니까? 그것은 우리의 목표가 무엇인지에 달려 있습니다!

이 모델의 원래 목표는 고객 유지를 예측하는 것이었습니다. 이는 재무 계획을 위한 미래 수익 추정과 같은 프로젝트에 유용합니다. 더 많은 버그를 보고하는 사용자는 실제로 갱신할 가능성이 더 높으므로 모델에서 이 관계를 캡처하는 것이 예측에 도움이 됩니다. 우리 모델이 표본 외부 적합성이 좋은 한 재무에 좋은 예측을 제공할 수 있으므로 모델에서 이러한 관계의 방향에 대해 걱정할 필요가 없습니다.

이는 예측 작업이라는 작업 클래스의 예입니다. 예측 작업의 목표는 일련의 특성 ‘X’를 바탕으로 결과 ’Y’(예: 갱신)를 예측하는 것입니다. 예측 연습의 핵심 구성 요소는 훈련 세트와 유사한 데이터 분포에서 ‘모델(X)’ 예측이 ‘Y’에 가깝다는 점에만 관심을 갖는다는 것입니다. ’X’와 ’Y’ 사이의 간단한 상관관계는 이러한 유형의 예측에 도움이 될 수 있습니다.

그러나 두 번째 팀이 더 많은 고객을 유지하기 위해 회사가 취할 수 있는 조치를 결정한다는 새로운 목표로 예측 모델을 선택한다고 가정해 보겠습니다. 이 팀은 학습 분포뿐만 아니라 세상이 변할 때 생성되는 반사실적 시나리오에서 각 ‘X’ 기능이 ‘Y’와 어떻게 관련되는지에 많은 관심을 갖고 있습니다. 이 사용 사례에서는 변수 간의 안정적인 상관 관계를 식별하는 것만으로는 더 이상 충분하지 않습니다. 이 팀은 ’X’ 기능을 조작하면 ’Y’가 변경되는지 알고 싶어합니다. 고객 갱신을 늘리기 위해 새로운 버그를 도입하기를 원한다고 엔지니어링 책임자에게 말할 때 그의 얼굴을 상상해 보십시오!

이는 원인이 되는 작업이라는 작업 클래스의 예입니다. 인과적 작업에서 우리는 세계 X의 측면 변경(예: 보고된 버그)이 결과 ‘Y’(갱신)에 어떻게 영향을 미치는지 알고 싶습니다. 이 경우 ’X’를 변경하면 ’Y’가 증가하는지, 아니면 데이터의 관계가 단지 상관 관계인지 여부를 아는 것이 중요합니다.

4.2 인과관계 추정의 과제

인과 관계를 이해하는 유용한 도구는 우리가 관심 있는 데이터 생성 프로세스의 인과 관계 그래프를 작성하는 것입니다. 우리 예의 인과 그래프는 XGBoost 고객 유지 모델에서 포착한 강력한 예측 관계가 유지율을 높이기 위해 개입을 계획하려는 팀의 관심 인과 관계와 다른 이유를 보여줍니다. 이 그래프는 실제 데이터 생성 메커니즘(위에 정의됨)을 요약한 것입니다. 속이 찬 타원은 우리가 관찰하는 특징을 나타내고 점선 타원은 측정하지 못하는 숨겨진 특징을 나타냅니다. 각 기능은 화살표가 있는 모든 기능과 일부 무작위 효과의 기능입니다.

이 예에서는 데이터를 시뮬레이션하기 때문에 인과 관계 그래프를 알고 있습니다. 실제로 진정한 인과관계 그래프는 알 수 없지만, 세상이 어떻게 작동하는지에 대한 상황별 도메인 지식을 사용하여 어떤 관계가 존재할 수 있거나 존재할 수 없는지 추론할 수 있습니다.

def marginal_effects(generative_model, num_samples=100, columns=None, max_points=20, logit=True, seed=0):
    """Helper function to compute the true marginal causal effects."""
    X = generative_model(num_samples)
    if columns is None:
        columns = X.columns
    ys = [[] for _ in columns]
    xs = [X[c].values for c in columns]
    xs = np.sort(xs, axis=1)
    xs = [xs[i] for i in range(len(xs))]
    for i, c in enumerate(columns):
        xs[i] = np.unique([np.nanpercentile(xs[i], v, method="nearest") for v in np.linspace(0, 100, max_points)])
        for x in xs[i]:
            Xnew = generative_model(num_samples, fixed={c: x}, seed=seed)
            val = Xnew["Did renew"].mean()
            if logit:
                val = scipy.special.logit(val)
            ys[i].append(val)
        ys[i] = np.array(ys[i])
    ys = [ys[i] - ys[i].mean() for i in range(len(ys))]
    return list(zip(xs, ys))

우리는 제품에 대한 관찰되지 않은 고객 요구로 인해 발생하는 할인에서도 비슷한 문제를 봅니다. 우리의 예측 모델은 실제로 갱신에 대한 할인의 작은 긍정적 인과 효과가 있음에도 불구하고 관찰되지 않은 기능인 제품 요구와의 이러한 상관 관계를 통해 할인과 유지 사이의 부정적인 관계를 찾습니다! 다르게 말하면, 동일한 제품 요구 사항을 갖고 있고 다른 점은 유사한 두 고객이 있는 경우 할인폭이 더 큰 고객이 갱신할 가능성이 더 높습니다.

또한 이 플롯은 예측 모델이 인과관계인 것처럼 해석하기 시작할 때 더 교활한 두 번째 문제를 드러냅니다. 광고 지출에도 비슷한 문제가 있다는 점에 주목하세요. 즉, 유지율에 인과 관계 효과는 없지만(검은색 선은 평평함) 예측 모델이 긍정적인 효과를 포착하고 있습니다.

이 경우 광고 지출은 마지막 업그레이드 및 월별 사용량에 의해서만 결정되므로 관찰되지 않은 교란 문제가 없고 대신 관찰된 교란 문제가 있습니다. 광고 지출과 광고 지출에 영향을 미치는 기능 간에는 통계적으로 중복성이 있습니다. 여러 특성에서 캡처한 동일한 정보가 있는 경우 예측 모델은 해당 특성이 모두 인과 관계가 아니더라도 예측에 이러한 특성을 사용할 수 있습니다. 광고 지출은 갱신 자체에 인과적인 영향을 미치지는 않지만, 갱신을 촉진하는 여러 기능과 밀접한 상관관계가 있습니다. 정규화된 모델은 여러 인과 요인을 요약하므로(따라서 희소 모델로 이어짐) 광고 지출을 유용한 예측 변수로 식별하지만, 이를 인과 효과로 해석하기 시작하면 심각한 오해를 불러일으킬 수 있습니다.

이제 예측 모델이 인과 관계 효과를 정확하게 측정할 수 있는 경우와 측정할 수 없는 경우를 설명하기 위해 예제의 각 부분을 차례로 다루겠습니다. 또한 예측 모델이 실패할 경우 인과 관계 효과를 추정할 수 있는 몇 가지 인과 도구도 소개합니다.

4.3 예측 모델이 인과적인 질문에 답할 수 있는 경우

우리 예의 성공부터 시작해 보겠습니다. 우리의 예측 모델은 경제 기능의 실제 인과 효과를 잘 포착합니다(더 나은 경제는 유지에 긍정적인 영향을 미칩니다). 그렇다면 예측 모델이 진정한 인과 관계 효과를 포착할 것으로 예상할 수 있는 때는 언제일까요?

XGBoost가 경제에 대한 좋은 인과 효과 추정치를 얻을 수 있게 해주는 중요한 요소는 기능의 강력한 독립 구성 요소입니다(이 시뮬레이션에서). 보존에 대한 예측력은 다른 측정된 특징이나 측정되지 않은 혼란 요인과 크게 중복되지 않습니다. 결과적으로 측정되지 않은 혼란 요인이나 기능 중복으로 인한 편향이 적용되지 않습니다.

SHAP 막대 그래프의 오른쪽에 클러스터링을 추가했기 때문에 데이터의 중복 구조를 덴드로그램으로 볼 수 있습니다. 덴드로그램의 하단(왼쪽)에서 기능이 병합되면 해당 기능에 포함된 결과(갱신)에 대한 정보가 매우 중복되어 모델이 두 기능 중 하나를 사용할 수 있음을 의미합니다. 덴드로그램의 상단(오른쪽)에서 기능이 병합되면 결과에 대해 포함된 정보가 서로 독립적이라는 의미입니다.

경제는 클러스터링 덴드로그램의 맨 위까지 다른 기능과 병합되지 않는다는 점에 주목하여 경제가 측정된 다른 모든 기능과 독립적이라는 것을 알 수 있습니다. 이는 경제가 관찰된 혼란으로 고통받지 않는다는 것을 말해줍니다. 그러나 경제 효과가 인과적이라는 것을 신뢰하려면 관찰되지 않은 혼란도 확인해야 합니다. 측정되지 않은 혼란 요인을 확인하는 것은 더 어렵고 도메인 지식(위 예에서 비즈니스 파트너가 제공)을 사용해야 합니다.

인과관계 결과를 제공하는 기존 예측 ML 모델의 경우 특성은 모델의 다른 특성뿐만 아니라 관찰되지 않은 혼란 요인과도 독립적이어야 합니다. 자연스럽게 이러한 수준의 독립성을 나타내는 관심 동인의 예를 찾는 것은 흔하지 않지만 데이터에 몇 가지 실험이 포함되어 있으면 독립적인 기능의 예를 찾을 수 있는 경우가 많습니다.

4.4 예측 모델이 인과관계 질문에 답할 수 없지만 인과 추론 방법이 도움이 될 수 있는 경우

대부분의 실제 데이터 세트의 특징은 독립적이지 않고 혼동되지 않으므로 표준 예측 모델은 실제 인과 효과를 학습하지 못합니다. 결과적으로 SHAP로 설명하면 인과관계가 드러나지 않습니다. 그러나 모든 것이 손실된 것은 아닙니다. 때로는 관찰 인과 추론 도구를 사용하여 이 문제를 수정하거나 최소한 최소화할 수 있습니다.

4.4.1 관찰된 교란

인과 추론이 도움이 될 수 있는 첫 번째 시나리오는 혼란스러운 관찰입니다. 원래 특성과 예측하는 결과 모두에 인과적으로 영향을 미치는 다른 특성이 있는 경우 특성이 “혼란”됩니다. 다른 특징을 측정할 수 있다면 이를 관찰된 혼란변수라고 합니다.

# Ad spend is very redundant with Monthly usage and Last upgrade.
shap.plots.bar(shap_values, clustering=clust, clustering_cutoff=1)

우리 시나리오에서 이에 대한 예는 광고 지출 기능입니다. 광고 지출이 유지율에 직접적인 영향을 미치지는 않지만 유지율을 높이는 마지막 업그레이드 및 월간 사용량 기능과 상관관계가 있습니다. 우리의 예측 모델은 상관 관계를 통해 수많은 실제 원인 동인을 포착하기 때문에 광고 지출을 유지율에 대한 최고의 단일 예측 변수 중 하나로 식별합니다. XGBoost는 정규화를 적용합니다. 이는 여전히 잘 예측하는 가장 간단한 가능한 모델을 선택하려고 시도한다는 멋진 표현입니다. 세 가지가 아닌 하나의 특성을 사용하여 똑같이 잘 예측할 수 있다면 과적합을 피하기 위해 그렇게 하는 경향이 있습니다. 그러나 이는 광고 지출이 마지막 업그레이드 및 월간 사용량과 높은 상관 관계가 있는 경우 XGBoost가 인과 기능 대신 광고 지출을 사용할 수 있음을 의미합니다! XGBoost(또는 정규화가 포함된 다른 기계 학습 모델)의 이러한 속성은 향후 유지율에 대한 강력한 예측을 생성하는 데 매우 유용하지만 유지율을 높이려면 어떤 기능을 조작해야 하는지 이해하는 데는 좋지 않습니다.

이는 각 질문에 적합한 모델링 도구를 연결하는 것의 중요성을 강조합니다. 버그 보고 예시와 달리, 광고 지출을 늘리면 유지율이 높아진다는 결론에는 직관적으로 잘못된 것이 없습니다. 우리의 예측 모델이 측정하는 것과 측정하지 않는 것이 무엇인지에 대한 적절한 주의가 없었다면 우리는 이 발견을 쉽게 진행할 수 있었으며 광고에 대한 지출을 늘리고 기대했던 갱신 결과를 얻지 못한 후에야 실수를 알게 되었습니다.

4.4.2 관찰적 인과 추론

광고 지출에 대한 좋은 소식은 혼란을 야기할 수 있는 모든 기능(위의 인과 그래프에서 광고 지출에 화살표가 있는 기능)을 측정할 수 있다는 것입니다. 따라서 이는 관찰된 교란의 예이며 이미 수집한 데이터만 사용하여 상관 패턴을 풀 수 있어야 합니다. 관찰적 인과 추론을 통해 올바른 도구를 사용하기만 하면 됩니다. 이러한 도구를 사용하면 광고 지출에 혼란을 줄 수 있는 기능을 지정한 다음 해당 기능에 맞게 조정하여 광고 지출이 제품 갱신에 미치는 인과 효과에 대한 혼란스럽지 않은 추정치를 얻을 수 있습니다.

관찰 인과 추론을 위한 특히 유연한 도구 중 하나는 이중/편향성 없는 기계 학습입니다. 먼저 관심 기능(예: 광고 지출)을 분석한 다음 해당 기능 변경의 평균 인과 효과(예: 인과 효과의 평균 기울기)를 추정하려는 기계 학습 모델을 사용합니다.

Double ML은 다음과 같이 작동합니다. 1. 가능한 혼란 요소(예: 광고 지출로 인해 발생하지 않은 모든 기능) 세트를 사용하여 관심 기능(예: 광고 지출)을 예측하도록 모델을 교육합니다. 2. 동일한 가능한 혼란 요인 세트를 사용하여 결과(예: 갱신했습니까)를 예측하도록 모델을 교육합니다. 3. 관심 있는 인과 특성의 잔차 변동을 사용하여 결과의 ​​잔차 변동(예측을 뺀 후 남은 변동)을 예측하도록 모델을 교육합니다.

직관에 따르면 광고 지출이 갱신을 유발하는 경우 다른 교란 특성으로 예측할 수 없는 광고 지출 부분은 다른 교란 특성으로 예측할 수 없는 갱신 부분과 상관관계가 있어야 합니다. 다르게 말하면, Double ML은 광고 지출에 영향을 미치는 독립적인(관찰되지 않은) 노이즈 특성이 있다고 가정하므로(광고 지출은 다른 특성에 의해 완벽하게 결정되지 않기 때문에) 이 독립적인 노이즈 특성의 값을 귀속시킨 다음 이 독립적인 특성에 대한 모델을 학습하여 출력을 예측할 수 있습니다.

모든 이중 ML 단계를 수동으로 수행할 수도 있지만 econML 또는 CausalML과 같은 인과 추론 패키지를 사용하는 것이 더 쉽습니다. 여기서는 econML의 LinearDML 모델을 사용합니다. 이는 해당 치료가 0이 아닌 인과 효과를 가지고 있는지 여부에 대한 P 값을 반환하고 시나리오에서 효과적으로 작동하여 갱신에 대한 광고 지출의 인과 효과에 대한 증거가 없음을 올바르게 식별합니다(P 값 = 0.85).

import matplotlib.pyplot as plt
from econml.dml import LinearDML
from sklearn.base import BaseEstimator, clone


class RegressionWrapper(BaseEstimator):
    """Turns a classifier into a 'regressor'.

    We use the regression formulation of double ML, so we need to approximate the classifer
    as a regression model. This treats the probabilities as just quantitative value targets
    for least squares regression, but it turns out to be a reasonable approximation.
    """

    def __init__(self, clf):
        self.clf = clf

    def fit(self, X, y, **kwargs):
        self.clf_ = clone(self.clf)
        self.clf_.fit(X, y, **kwargs)
        return self

    def predict(self, X):
        return self.clf_.predict_proba(X)[:, 1]


# Run Double ML, controlling for all the other features
def double_ml(y, causal_feature, control_features):
    """Use doubleML from econML to estimate the slope of the causal effect of a feature."""
    xgb_model = xgboost.XGBClassifier(objective="binary:logistic", random_state=42)
    est = LinearDML(model_y=RegressionWrapper(xgb_model))
    est.fit(y, causal_feature, W=control_features)
    return est.effect_inference()


def plot_effect(effect, xs, true_ys, ylim=None):
    """Plot a double ML effect estimate from econML as a line.

    Note that the effect estimate from double ML is an average effect *slope* not a full
    function. So we arbitrarily draw the slope of the line as passing through the origin.
    """
    plt.figure(figsize=(5, 3))

    pred_xs = [xs.min(), xs.max()]
    mid = (xs.min() + xs.max()) / 2
    [effect.pred[0] * (xs.min() - mid), effect.pred[0] * (xs.max() - mid)]

    plt.plot(xs, true_ys - true_ys[0], label="True causal effect", color="black", linewidth=3)
    point_pred = effect.point_estimate * pred_xs
    pred_stderr = effect.stderr * np.abs(pred_xs)
    plt.plot(
        pred_xs,
        point_pred - point_pred[0],
        label="Double ML slope",
        color=shap.plots.colors.blue_rgb,
        linewidth=3,
    )
    # 99.9% CI
    plt.fill_between(
        pred_xs,
        point_pred - point_pred[0] - 3.291 * pred_stderr,
        point_pred - point_pred[0] + 3.291 * pred_stderr,
        alpha=0.2,
        color=shap.plots.colors.blue_rgb,
    )
    plt.legend()
    plt.xlabel("Ad spend", fontsize=13)
    plt.ylabel("Zero centered effect")
    if ylim is not None:
        plt.ylim(*ylim)
    plt.gca().xaxis.set_ticks_position("bottom")
    plt.gca().yaxis.set_ticks_position("left")
    plt.gca().spines["right"].set_visible(False)
    plt.gca().spines["top"].set_visible(False)
    plt.show()


# estimate the causal effect of Ad spend controlling for all the other features
causal_feature = "Ad spend"
control_features = [
    "Sales calls",
    "Interactions",
    "Economy",
    "Last upgrade",
    "Discount",
    "Monthly usage",
    "Bugs reported",
]
effect = double_ml(y, X[causal_feature], X.loc[:, control_features])

# plot the estimated slope against the true effect

이중 ML(또는 기타 관찰 인과 추론 방법)은 인과 효과를 추정하려는 특성의 가능한 모든 혼란 요인을 측정하고 식별할 수 있는 경우에만 작동한다는 점을 기억하세요. 여기서 우리는 인과 관계 그래프를 알고 있으며 월간 사용량과 마지막 업그레이드가 우리가 제어해야 하는 두 가지 직접적인 혼란 요인임을 알 수 있습니다. 그러나 인과 관계 그래프를 모른다면 SHAP 막대 그래프의 중복성을 살펴보고 월간 사용량과 마지막 업그레이드가 가장 중복되는 기능이므로 제어할 수 있는 좋은 후보임을 알 수 있습니다(할인 및 보고된 버그도 마찬가지).

4.4.3 혼란스럽지 않은 중복성

인과 추론이 도움이 될 수 있는 두 번째 시나리오는 혼란을 주지 않는 중복성입니다. 이는 인과관계에 대한 인과 효과를 원하는 특성이 모델에 포함된 다른 특성을 인과적으로 유도하거나 이에 의해 유도되지만 해당 다른 특성이 관심 특성을 혼란스럽게 하지 않는 경우에 발생합니다.

# Interactions and sales calls are very redundant with one another.
shap.plots.bar(shap_values, clustering=clust, clustering_cutoff=1)

이에 대한 예로 판매 통화 기능이 있습니다. 영업 통화는 고객 유지에 직접적인 영향을 미치지만 상호작용을 통해 고객 유지에 간접적인 영향을 주기도 합니다. 모델에 상호 작용 및 판매 통화 기능을 모두 포함하면 두 기능이 공유하는 인과 효과가 둘 사이에 분산됩니다. 위의 SHAP 분산형 차트에서 이를 볼 수 있는데, 이는 대부분의 효과가 상호 작용 기능에 적용되었기 때문에 XGBoost가 판매 통화의 실제 인과 효과를 어떻게 과소평가하는지 보여줍니다.

교란되지 않는 중복은 원칙적으로 모델에서 중복 변수를 제거하여 수정할 수 있습니다(아래 참조). 예를 들어 모델에서 상호 작용을 제거하면 갱신 확률에 대한 판매 요청의 전체 효과를 포착할 수 있습니다. 관심 있는 특성으로 인해 발생하는 다운스트림 특성을 제어하는 ​​경우 이중 ML은 간접적인 인과 효과를 포착하지 못하기 때문에 이러한 제거는 이중 ML에도 중요합니다. 이 경우 이중 ML은 다른 기능을 통과하지 않는 “직접” 효과만 측정합니다. 그러나 Double ML은 업스트림 비교란 중복성(중복 기능으로 인해 관심 기능이 발생하는 경우)을 제어하는 ​​데 강력하지만 이로 인해 실제 효과를 감지하는 통계적 능력이 감소합니다.

불행하게도 우리는 실제 인과 관계 그래프를 모르는 경우가 많으므로 교란 중복과 비교란 중복으로 인해 다른 특성이 관심 특성과 중복되는 시기를 알기 어려울 수 있습니다. 교란으로 인한 것이라면 이중 ML과 같은 방법을 사용하여 해당 기능을 제어해야 하는 반면, 다운스트림 결과인 경우 직접적인 효과보다는 완전한 인과 효과를 원한다면 모델에서 기능을 삭제해야 합니다. 제어해서는 안되는 기능을 제어하면 인과 효과를 숨기거나 분리하는 경향이 있는 반면, 제어해야 하는 기능을 제어하지 못하면 존재하지 않는 인과 효과를 추론하는 경향이 있습니다. 이는 일반적으로 불확실할 때 기능을 제어하는 ​​것이 더 안전한 옵션이 됩니다.

# Fit, explain, and plot a univariate model with just Sales calls

4.5 예측 모델이나 혼란을 방지하는 방법 모두 인과 관계 질문에 답할 수 없는 경우

이중 ML(또는 혼동되지 않는다고 가정하는 기타 인과 추론 방법)은 인과 효과를 추정하려는 특성의 가능한 모든 혼란 요인을 측정하고 식별할 수 있는 경우에만 작동합니다. 모든 혼란 요인을 측정할 수 없다면 가장 어려운 시나리오, 즉 관찰되지 않은 혼란 상황에 처하게 됩니다.

# Discount and Bugs reported seem are fairly independent of the other features we can
# measure, but they are not independent of Product need, which is an unobserved confounder.
shap.plots.bar(shap_values, clustering=clust, clustering_cutoff=1)

할인 및 보고된 버그 기능은 모두 중요한 변수(예: 제품 요구 사항 및 직면한 버그)가 데이터에서 측정되지 않기 때문에 관찰되지 않은 혼란으로 인해 어려움을 겪습니다. 두 기능 모두 모델의 다른 모든 기능과 상대적으로 독립적이지만 측정되지 않은 중요한 동인이 있습니다. 이 경우 예측 모델과 이중 ML과 같이 혼란 요인을 관찰해야 하는 인과 모델이 모두 실패합니다. 이것이 Double ML이 관찰된 다른 모든 특성을 제어할 때에도 할인 특성에 대해 큰 부정적인 인과 효과를 추정하는 이유입니다.

# estimate the causal effect of Ad spend controlling for all the other features
causal_feature = "Discount"
control_features = [
    "Sales calls",
    "Interactions",
    "Economy",
    "Last upgrade",
    "Monthly usage",
    "Ad spend",
    "Bugs reported",
]
effect = double_ml(y, X[causal_feature], X.loc[:, control_features])

# plot the estimated slope against the true effect
xs, true_ys = marginal_effects(generator, 10000, X[[causal_feature]], logit=False)[0]
plot_effect(effect, xs, true_ys, ylim=(-0.5, 0.2))

이전에 측정되지 않은 특징(또는 이와 연관된 특징)을 측정하는 능력을 제외하면, 관찰되지 않은 교란이 있는 경우 인과 관계 효과를 찾는 것은 어렵습니다. 이러한 상황에서 정책에 영향을 줄 수 있는 인과 효과를 식별하는 유일한 방법은 관심 있는 특징과 측정되지 않은 혼란 요인 간의 상관 관계를 깨뜨리는 무작위화를 생성하거나 활용하는 것입니다. 무작위 실험은 이러한 맥락에서 인과 관계 효과를 찾기 위한 최적의 표준으로 남아 있습니다.

도구 변수, 차이 차이 또는 회귀 불연속성의 원리를 기반으로 하는 특수 인과 도구는 전체 실험이 불가능한 경우에도 때때로 부분 무작위화를 활용할 수 있습니다. 예를 들어 도구 변수 기술을 사용하면 치료법을 무작위로 할당할 수 없는 경우 인과 효과를 식별할 수 있지만 일부 고객에게 새로운 제품 기능을 탐색하도록 격려하는 이메일을 보내는 것과 같이 무작위로 일부 고객을 치료법으로 유도할 수 있습니다. 차이의 차이 접근법은 새로운 치료법의 도입이 그룹 간에 시차를 두고 있을 때 도움이 될 수 있습니다. 마지막으로, 회귀 불연속 접근법은 치료 패턴이 급격하게 구분되는 경우(예: 월 $5,000 이상의 수익과 같은 구체적이고 측정 가능한 특성을 기반으로 한 치료 자격)에 좋은 옵션입니다.

4.6 요약

XGBoost 또는 LightGBM과 같은 유연한 예측 모델은 예측 문제를 해결하기 위한 강력한 도구입니다. 그러나 본질적으로 인과 모델은 아니므로 SHAP로 해석하면 많은 일반적인 상황에서 인과 관계 질문에 정확하게 대답하지 못할 것입니다. 모델의 특징이 실험적 변형의 결과가 아닌 이상 교란을 고려하지 않고 예측 모델에 SHAP를 적용하는 것은 일반적으로 정책을 알리는 데 사용되는 인과적 영향을 측정하는 적절한 도구가 아닙니다. SHAP 및 기타 해석 도구는 인과 추론에 유용할 수 있으며 SHAP는 많은 인과 추론 패키지에 통합되어 있지만 이러한 사용 사례는 본질적으로 명시적인 인과입니다. 이를 위해 예측 문제에 대해 수집하는 것과 동일한 데이터를 사용하고 인과 관계 효과를 반환하도록 특별히 설계된 이중 ML과 같은 인과 추론 방법을 사용하는 것이 정책을 알리는 데 좋은 접근 방식인 경우가 많습니다. 다른 상황에서는 실험이나 기타 무작위 소스만 실제 질문에 답할 수 있습니다. 인과 추론을 위해서는 항상 중요한 가정을 해야 합니다. 이 기사의 주요 요점은 일반적인 예측 모델을 인과 관계로 해석하여 내리는 가정이 종종 비현실적이라는 것입니다.
