57  심플 캘리포니아 데모 2.0

이 노트북은 입력 기능의 계층적 클러스터링을 구축하고 이를 사용하여 단일 인스턴스를 설명하는 방법을 보여줍니다. 이를 수행하는 두 가지 방법을 보여줍니다.

선택한 scipy 클러스터링 방법을 사용하여 기능의 이진 계층 클러스터링을 생성하는 PartitionExplainer. 그런 다음 PartitionExplainer는 이 이진 파티션 트리에 대한 한계를 사용하여 기능 속성을 계산합니다. 이는 입력 특성의 수가 많을 때 단일 인스턴스를 설명하는 좋은 방법입니다. 균형 잡힌 파티션 트리가 주어지면 PartitionExplainer에는 \(O(M^2)\) 런타임이 있으며, 여기서 \(M\)은 입력 기능의 수입니다. 이는 KernelExplainer의 \(O(2^M)\) 런타임보다 훨씬 낫습니다.

CoalitionExplainer를 사용하면 기능 계층을 더 효과적으로 제어할 수 있습니다. 사용자는 기능의 중첩된 계층 구조를 사전으로 지정할 수 있습니다. 이는 각 노드(기능 그룹)가 둘 이상의 노드를 허용하는 모든 형제 노드에 대한 한계 기여를 할당받는다는 것을 의미합니다. 따라서 각 수준의 계산 복잡성은 \(O(2^K)\)입니다. 여기서 \(K\)는 형제 수이며 지정된 기능의 계층 구조에 따라 달라집니다. 이 방법을 사용하면 모델 작동에 대한 보다 합리적인 설명과 보다 세밀한 평가가 가능합니다.

전문 용어를 명확히 하기 위해 Shapley 값은 모든 입력 특성을 동일하게 취급합니다. 오웬 값은 특성 연합을 존중하는 값입니다. Winter 값이라고도 하는 재귀적 Owen 값은 중첩된 연합을 존중합니다.

57.3 인스턴스 설명

CoalitionExplainer의 새로운 동작을 시연하고 올바르게 작동하는지 확인하기 위해 ExactExplainer 및 PartitionExplainer 메서드를 사용할 수 있습니다.

이론적으로 CoalitionExplainer에 평면 계층 구조를 전달하면 ExactExplainer와 동일한 결과를 반환해야 합니다.

PartitionExplainer가 사용하는 연결 매트릭스를 사전으로 변환하고 이를 CoalitionExplainer에 전달하면 Partition explainer와 정확히 동일한 결과를 반환해야 합니다.

# function to turn the linkage matrix to a dictionary
def build_partition_hierarchy(linkage, labels):
    n = len(labels)
    cluster_dict = {}

    # Initialize leaves
    for i in range(n):
        cluster_dict[i] = labels[i]

    # Build clusters
    for i, row in enumerate(linkage):
        idx1 = int(row[0])
        idx2 = int(row[1])
        cluster_id = n + i  # New cluster index

        # Create cluster names
        if idx1 < n:
            left = cluster_dict[idx1]
        else:
            left = f"cluster_{idx1}"

        if idx2 < n:
            right = cluster_dict[idx2]
        else:
            right = f"cluster_{idx2}"

        # Create the new cluster
        cluster_dict[cluster_id] = {left: cluster_dict[idx1], right: cluster_dict[idx2]}

    # The root cluster
    root_cluster_id = n + len(linkage) - 1
    return {f"cluster_{root_cluster_id}": cluster_dict[root_cluster_id]}

def add_nodes_edges(graph, parent_name, parent_dict):
    for key, value in parent_dict.items():
        if isinstance(value, dict):
            graph.add_node(key)
            graph.add_edge(parent_name, key)
            add_nodes_edges(graph, key, value)
        else:
            graph.add_node(value)
            graph.add_edge(parent_name, value)


def hierarchy_pos(G, root=None, width=1.0, vert_gap=0.2, vert_loc=0, xcenter=0.5):
    pos = _hierarchy_pos(G, root, width, vert_gap, vert_loc, xcenter)
    return pos


def _hierarchy_pos(
    G,
    root,
    width=1.0,
    vert_gap=0.2,
    vert_loc=0,
    xcenter=0.5,
    pos=None,
    parent=None,
    parsed=[],
):
    if pos is None:
        pos = {root: (xcenter, vert_loc)}
    else:
        pos[root] = (xcenter, vert_loc)

    children = list(G.neighbors(root))
    if not isinstance(G, nx.DiGraph) and parent is not None:
        children.remove(parent)

    if len(children) != 0:
        dx = width / len(children)
        nextx = xcenter - width / 2 - dx / 2
        for child in children:
            nextx += dx
            pos = _hierarchy_pos(
                G,
                child,
                width=dx,
                vert_gap=vert_gap,
                vert_loc=vert_loc - vert_gap,
                xcenter=nextx,
                pos=pos,
                parent=root,
                parsed=parsed,
            )

    return pos
